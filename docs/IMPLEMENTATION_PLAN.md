# 实现计划 · 音准可视化（Pitch Scope）

> 本文记录“为什么这样做、怎么拆模块、哪些是假设”。运行方式与操作说明见根目录 `README.md`。

## 1. 目标

做一个**本地、低延迟、只服务于单音人声音准**的可视化工具：

```
麦克风 / 系统声音 → 单音基频估计 → 十二平均律音名/八度/音分 → 实时“时间–音高”曲线
```

用户练习唱歌时，能在 100–150 ms 内看到自己当前唱到哪个音、偏高还是偏低、曲线往哪走。系统声音来源用于把视频、游戏、播放器里的单声部旋律接进同一条分析链。

## 2. 产品边界（硬约束）

### 2.1 做

- 单声部、单音的人声基频检测
- 音名 + 八度 + 相对最近音名的音分偏差 + 置信度
- 实时音高曲线，纵轴 CDEFGAB 音名刻度
- 目标音参考线（视觉参考）
- A4 参考频率可配置，默认 440 Hz
- 状态：信号不足 / 检测中 / 低置信度 / 超出范围 / 输入过载 / 音频中断
- 输入电平、设备选择
- 系统声音输入（浏览器共享屏幕音频），与麦克风共用同一条分析链

### 2.2 不做

- 评分、得分、等级、命中率、平均偏差统计、练习报告、排行榜、唱功评价
- 音色、气息、节奏、情感评价，唱法诊断
- 复音、和弦、多人同时演唱
- 全频段频谱分析仪，频谱不作为主界面
- 录音、导出、云端上传

## 7. 关键算法决策

### 7.1 为什么是 YIN，而不是 FFT 峰值

FFT 的频率分辨率受窗口长度限制：4096 点 @48 kHz 约 11.7 Hz/bin，C4 附近 1 bin ≈ 77 cents，无法满足 ±5 cents 的读数。YIN 在时域做自相关式差分，配合抛物线插值可以得到远高于 FFT bin 的精度；且对单声部人声的周期判断更直接。

### 7.2 两级搜索：降采样粗估 + 原始采样率细化

C2（65 Hz）周期约 738 samples @48 kHz；C6（1046 Hz）周期约 46 samples。若全程在原始采样率做 YIN，C2 的 `tauMax` 很大，差分函数计算量高。

实现：

1. 2 倍降采样（相邻样本均值，兼作粗低通），在 `dsr = sr/2` 上算差分函数与累积均值归一化，取第一个低于阈值 0.15 的局部极小。
2. 把候选 `tau` 乘回 2，在原始采样率上、候选附近 ±(dec+2) 个 lag 内重算差分，取最小。
3. 对最小点做抛物线插值，得到亚样本精度的 `tau`，`f0 = sr / tau`。

精度实测：C2–C6 十个标准音中位误差 0.00 cents（C6 为 0.01），P95 < 5 cents。

### 7.3 范围外高频不被误读为低八度

YIN 的搜索上限如果刚好卡在 `maxFreq`，1.4 kHz 的输入可能被读成 700 Hz（低八度）。实现把搜索上限放宽到 `maxFreq * 1.5`，先测出真实基频，再由 `inRange` 标记为“超出范围”，返回 `f0=0` 但保留 `rawF0` 供调试。这样 1400 Hz / 40 Hz 都会被正确拒绝。

### 7.4 平滑与倍频跳变抑制

`PitchSmoother`：

- 先把 `f0` 转到 `log2` 域（音分/半音是线性关系）
- 中值滤波（3 或 5 点）去掉单帧离群值
- 指数平滑（τ = 30 / 55 ms）
- **跳变保护**：中值与当前平滑值相差超过 0.5 octave（约 6 个半音）时，先保持旧值；连续两帧都成立才接受。真实八度跳变约 2 帧（~42 ms）后生效，单帧误检不会在曲线上留下尖刺。

### 7.5 状态机

```
idle → starting → detecting
                 ├→ no-signal      电平 < gate
                 ├→ low-confidence rawF0=0 或 aperiodicity > 1-confidence
                 ├→ out-of-range   midiFloat 超出音域 ±0.35
                 ├→ overload       clipRatio > 5%
                 ├→ stalled        1.5 s 无消息（watchdog）
                 ├→ stopped        用户停止
                 └→ error          权限 / 设备 / worklet 异常
```

只有 `detecting` 才写 `state.current` 与 `state.history`；其它状态清空当前音高、重置平滑器，曲线自然断开。这样“无声时误报音名”在状态机层面就被禁止，而不是靠 UI 遮挡。

系统声音共享结束时走 `stop("source-ended")`，落到 `stopped`；麦克风 `track.ended` 仍按“设备断开”走 `stalled`。

### 7.6 音名映射

```
midiFloat = 69 + 12 * log2(f / A4)
midi      = round(midiFloat)
cents     = (midiFloat - midi) * 100
label     = NOTE_NAMES[midi mod 12] + (floor(midi/12) - 1)
```

`freqToNote()` 一次返回 `midi / midiFloat / cents / note / octave / label / targetFreq`，UI 不需要重复算。

## 8. UI 设计决策

- **形态**：硬件调音台 / 示波器面板，而不是 SaaS 卡片。深色仪表底 `#0a1011`、黄铜强调 `#d7b26c`、曲线青 `#78c9b6`、等宽数字。
- **主界面排序**：左侧“当前音高”读数（大号音名 → 音分条 → 电平 → 频率），右侧整块“即时音高”曲线。曲线是视觉主体，不被卡片切碎。
- **不做频谱**：主界面没有频谱图；调试信息折叠在“调试信息”里，只有基频、Aperiodicity、削波比例等标量。
- **曲线纵轴**：CDEFGAB 音名。48 个半音挤在 ~350 px 时，只标注 C 与 A；间距变大后自动标注全部自然音级；再大则显示半音网格。避免标签互相压叠。
- **断线**：折线在相邻点时间差 > 0.22 s 时 `moveTo`，低置信度区间自然断开，不画“确定音高点”。
- **响应式**：>1020 px 双列 + 100vh 不滚动；≤1020 px 单列、页面可滚动；≤640 px 控件纵向堆叠。
- **无障碍**：所有按钮有 `aria-label` / `aria-pressed`；键盘焦点可见；`prefers-reduced-motion` 关闭过渡。

## 12. 风险与未决项

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 用户设备 / 驱动的降噪、AGC 无法完全关闭 | 弱音被吞、音高抖动 | 代码请求关闭；README 说明；门限可调 |
| 蓝牙耳机延迟 | 实时性变差 | 界面延迟为估算值；README 说明建议有线麦 |
| 低音 C2 拾音弱 | 低音区显示“信号不足” | 音域可收窄；建议耳机麦 / USB 麦 |
| 移动端 AudioWorklet 支持差异 | 手机不可用 | 明确桌面为主；Android 方案见 ROADMAP |
| 系统声音依赖屏幕共享 | 交互重、共享画面有隐私顾虑 | README 说明；Windows 桌面版用 Electron loopback 去掉共享选择器 |
| DRM / 独占模式音频捕获不到 | 部分视频、游戏没有输入 | 明确列为已知限制，不当作算法 bug |
| 系统回环里多个声源叠加 | YIN 只能跟最强单音 | 产品边界：只做单声部；不扩展复音 |
| 真实人声的强泛音 / 气声 | YIN 置信度下降 | 低置信度断线，不硬报音名 |
| 无麦克风的自动化环境 | 无法自动验收整机 | 提供 WAV + 人工验收清单；算法层已自动测试 |

**未决项（需要用户确认）**：是否要在后续版本加入“音域快捷预设（如男声/女声）”、曲线缩放、录音回放。当前版本刻意不做，避免越过“只做音准可视化”的边界。
